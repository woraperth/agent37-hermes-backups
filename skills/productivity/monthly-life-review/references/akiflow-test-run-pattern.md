# Reference: Akiflow Month-to-Date Test Run

## Validated source pattern

For a test run in an incomplete month, query Akiflow over the first day of the month through the current local date (or through month-end when a forward horizon is useful), including completed tasks, open tasks, overdue state, and events. Summarise counts and patterns rather than pasting the full response.

## Example evidence shape

A useful review can report:

- total tasks and events in the window
- overdue task count
- open high-priority items
- major project/topic concentration
- examples of different friction types: time-sensitive communication, operational setup, blocked/waiting work, and routine maintenance
- upcoming event load that constrains capacity

## Interpretation guardrails

A large task list is evidence of workload and open loops, not proof of poor discipline. Check whether items are future-scheduled, vague, waiting on another person, recurring maintenance, or exploratory ideas. An item such as “wait for support” should usually become a waiting record with a follow-up date rather than remain an overdue action.

If only Akiflow was inspected, call the result a workload/calendar review and list uninspected areas such as finances, health, relationships, and Obsidian notes. Use provisional wording for conclusions.

## User-facing style

For Perth in Discord: relaxed medium-length bullets, readable headings, no raw IDs or API JSON, and one reflective question at the end. Continue interactively one question at a time after the initial report.
